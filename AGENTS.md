# TeaTimer Landing Page Working Rules

## Project goal

This repository contains the landing page for the TeaTimer app.

The landing page should always stay:
- modern
- premium
- simple
- mobile-friendly
- clean
- elegant
- consistent with the TeaTimer brand

Use a warm, minimal, Apple-like visual style.

## General rules

- Keep the design clean and professional.
- Keep the page responsive on mobile, tablet, and desktop.
- Keep the style consistent with the existing TeaTimer landing page.
- Reuse existing assets when possible.
- Do not remove important sections unless I explicitly ask.
- Do not delete videos, images, icons, screenshots, or brand assets without listing them first.
- Do not overwrite working files without checking the current structure first.
- Do not push directly to main.
- Do not merge into main.
- Always work on a feature branch for important changes.
- After every change, explain clearly what changed and how I can preview it.

## Start a new feature safely

For every important new change:

1. Check the current branch.
2. If we are on main, create a new branch called:

feature-[short-feature-name]

Use a clear branch name based on the requested change.

Examples of branch names:
- feature-hero-update
- feature-waitlist-section
- feature-video-background
- feature-mobile-polish
- feature-screenshot-gallery

3. Add the requested feature or change.
4. Keep the style consistent and mobile-friendly.
5. Do not push directly to main.
6. Do not merge into main.

After finishing, show me:
- branch name
- changed files
- what you added or changed
- how to preview it
- anything I should check manually

## Preview the change

After creating or editing a feature, use the available preview system.

Check that:
- the design looks good
- the feature works
- the mobile version is okay
- nothing important broke
- images and videos still load correctly
- buttons and links still work
- layout spacing is clean

If there is a problem, fix it before asking me to review.

## Commit and push workflow

Only after the feature is finished and previewed, wait for my approval before committing if the change is important.

When I approve, commit with a clear message.

Example:

Commit these changes with the message:
"Update TeaTimer landing page hero section"

Push this feature branch to GitHub.
Do not merge into main.

## Final report format

After every completed task, report:

1. Branch name
2. Changed files
3. What was added or changed
4. How to preview locally
5. Whether mobile was checked
6. Whether anything may need my attention
7. Whether the branch was pushed or not

## Important safety rules

- Never push directly to main.
- Never merge without my explicit approval.
- Never delete assets unless I clearly ask.
- Never remove videos, images, icons, screenshots, or brand assets without listing them first.
- Never make the landing page look generic or messy.
- If you are unsure, stop and ask.
- Keep the landing page simple, premium, and professional.
